# 🌿 PlantCare

Мобильное PWA для ухода за домашними и садовыми растениями. Приложение хранит сад и историю ухода локально в браузере, умеет работать без сети после первого посещения и устанавливается на домашний экран.

## Локальный запуск

Требуется Node.js 20+ и npm 10+.

```bash
git clone <URL-вашего-репозитория>
cd Plant-Care
npm install
npm run dev
```

Vite покажет локальный адрес (обычно `http://localhost:5173`). Для проверки production-сборки:

```bash
npm run build
npm run preview
```

> Service Worker регистрируется только в production-режиме, чтобы его кэш не мешал разработке. Проверяйте офлайн-режим через `npm run build && npm run preview`.

## Деплой из GitHub на Vercel

1. Загрузите репозиторий на GitHub.
2. В Vercel выберите **Add New → Project** и импортируйте репозиторий.
3. Vercel автоматически определит Vite. Настройки уже зафиксированы в `vercel.json`: команда сборки — `npm run build`, каталог результата — `dist`.
4. Нажмите **Deploy**. Переменные окружения не нужны.

Каждый последующий push в основную ветку будет создавать новый production deployment, а pull request — preview deployment.

## PWA-возможности

- Web App Manifest с отдельными обычной и maskable иконками;
- standalone-режим, системный цвет темы и поддержка safe area на iPhone;
- предложение установки в поддерживаемых браузерах;
- Service Worker с офлайн-кэшем оболочки и собранных ресурсов;
- понятный индикатор потери сети;
- ярлыки «Мои растения» и «Добавить растение»;
- корректные заголовки кэширования Service Worker на Vercel.

Каталожные изображения и научные данные GBIF требуют интернет. Все пользовательские растения, заметки и события ухода остаются доступны локально.

## Данные и приватность

Данные пользователя не отправляются на сервер и сохраняются в `localStorage`. Используйте встроенный экспорт резервной копии перед очисткой данных браузера или сменой устройства.

## Рекомендации для следующего этапа

1. Перенести фотографии и данные сада из `localStorage` в IndexedDB, чтобы увеличить допустимый объём и сделать запись надёжнее.
2. Добавить опциональную авторизацию и облачную синхронизацию между устройствами.
3. Разделить крупный `App.tsx` на каталог, хранилище, экраны и модальные окна; добавить unit- и e2e-тесты.
4. Реализовать настоящую диагностику через специализированный API вместо симуляции и явно маркировать уверенность результата.
5. Добавить фоновые push-уведомления через серверную подписку; локальные напоминания без запущенного приложения ограничены платформой.
6. Кэшировать ответы GBIF с TTL в IndexedDB и показывать дату актуальности научных данных.
7. Добавить редактирование имени и интервалов, подтверждение удаления, поиск по своему саду и доступную тёмную тему.

## Обширный справочник растений

В каталоге работает объединённый поиск: проверенные карточки PlantCare доступны локально, а при вводе не менее трёх символов приложение ищет таксоны царства растений в глобальной базе GBIF. Внешний вид можно добавить в сад — его название и латинское имя сохранятся локально и останутся доступными офлайн. Научная запись не считается автоматически проверенной инструкцией по домашнему уходу.

Подробная стратегия расширения данных, перечень следующих справочников и критерии качества находятся в [`docs/ROADMAP.md`](docs/ROADMAP.md).

Каталог разделён на feature-модули в `src/features/catalog`: редакционные данные, общие типы, GBIF-клиент и экран поиска.
Глобальная выдача поддерживает загрузку следующих страниц и кэширует поисковые ответы на время браузерной сессии.

```bash
npm test       # unit-тесты преобразования внешних записей
npm run build  # production-сборка
```

## Нулевой бюджет на сервисы

Проект принципиально использует только бесплатные публичные API, открытые данные, open-source зависимости и локальные возможности браузера. Платные API, trial-only сервисы и ключи с обязательным billing не допускаются. Основные функции сада не должны зависеть от доступности внешнего сервиса.

Правила выбора и проверки интеграций описаны в [`docs/FREE_SERVICES_POLICY.md`](docs/FREE_SERVICES_POLICY.md). Это ограничение также закреплено в корневом `AGENTS.md` для всех будущих изменений.

## Перенос сада между устройствами

Vercel хранит только статическую сборку приложения и не получает пользовательские данные. В разделе **Мои данные** можно скачать полный `plantcare-YYYY-MM-DD.json`, передать его на другое устройство и импортировать на том же Vercel-сайте. JSON v2 включает растения, фотографии, историю ухода, заметки, напоминания, внешние GBIF-ссылки и переносимые настройки; старые backup-файлы v1 мигрируются при чтении.

Подробная инструкция и ограничения браузерного файлового доступа описаны в [`docs/DATA_PORTABILITY.md`](docs/DATA_PORTABILITY.md).

## ИИ Садовод

Плавающая кнопка ИИ-помощника постоянно находится в правом нижнем углу приложения и доступна на всех вкладках. Если открыта карточка растения, помощник получает только локальный контекст этой карточки; в остальных случаях работает как общий садовый помощник. На Vercel каждый пользователь получает бесплатный ответ от встроенного офлайн-эксперта; доступная browser-модель или локальный Ollama могут улучшить ответ, но не обязательны. Подробности: [`docs/ASSISTANT.md`](docs/ASSISTANT.md).

Краткая рабочая последовательность ограничена 18 шагами: от regression baseline и декомпозиции сада до IndexedDB, бесплатных уведомлений и стабильного Vercel-релиза. Каждый шаг имеет проверяемый результат и выполняется без изменения текущего дизайна.

## PWA-иконки и Git

PNG-иконки не хранятся как бинарные файлы в Git: `scripts/generate-icons.mjs` детерминированно создаёт размеры 180, 192 и 512 пикселей. Скрипты `npm run dev` и `npm run build` запускают генерацию автоматически, поэтому локальный запуск и Vercel получают полный набор иконок без бинарных файлов в pull request.

## Редактирование карточек и заметки

В детальной карточке растения кнопка с карандашом позволяет изменить название, описание, интервалы ухода, добавить, заменить или удалить пользовательское фото. Удаление растения всегда требует отдельного подтверждения. В заметках кнопки **Маркер** и **Чекбокс** вставляют элементы списка, а сохранённые чекбоксы можно отмечать и снимать прямо в заметке; состояние входит в локальное хранилище и JSON backup.
