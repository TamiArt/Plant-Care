# План развития PlantCare

> **Непереговорное ограничение:** приложение строится только на бесплатных сервисах, открытых данных и open-source решениях. Платные API, trial-only сервисы и ключи с обязательным billing запрещены. Полные критерии: [`FREE_SERVICES_POLICY.md`](FREE_SERVICES_POLICY.md).

Пошаговый технический порядок работ без изменения текущего дизайна описан в [`IMPLEMENTATION_PLAN.md`](IMPLEMENTATION_PLAN.md).

Приоритетный продуктовый backlog для ежедневного ухода описан в [`PRODUCT_BACKLOG.md`](PRODUCT_BACKLOG.md).

## Принцип каталога

Невозможно безопасно поддерживать «все растения мира» статическим массивом в приложении: научные названия меняются, число таксонов измеряется сотнями тысяч, а инструкции по уходу зависят от сорта и условий. Поэтому каталог разделён на два слоя:

1. **Редакционный каталог PlantCare** — проверенные бытовые инструкции и интервалы ухода, доступные офлайн.
2. **Глобальный научный поиск GBIF** — обширный актуализируемый справочник растений по русским, народным и латинским названиям. Результат можно добавить в сад, самостоятельно настроив полив.

Научная классификация не должна автоматически превращаться в совет по уходу. Для внешних видов интерфейс явно отделяет справочные сведения от приблизительной стартовой настройки.

## Реализовано в текущем этапе

- Поиск по царству Plantae в GBIF с задержкой ввода и отменой устаревших запросов.
- Дедупликация таксонов, отображение статуса, ранга и семейства.
- Объединённая выдача локального каталога и глобальной базы.
- Состояния загрузки, отсутствия результатов, офлайн-режима и ошибки API.
- Сохранение внешнего растения как автономной записи: название не пропадает после перезагрузки или без интернета.
- Научная карточка GBIF с классификацией, народными названиями и фотографиями наблюдений.
- Редакционный каталог, типы, GBIF-клиент и экран поиска вынесены из монолитного `App.tsx` в `src/features/catalog`.
- Добавлены постраничная выдача GBIF, кнопка «Показать ещё» и суточный кэш страниц поиска в `sessionStorage`.
- В растении сохраняется внешний идентификатор GBIF, scientific name, rank, status и дата получения.
- Добавлены автоматические тесты преобразования GBIF-записей и сохранения внешней ссылки.
- Добавлен переносимый JSON v2 со всеми данными сада и настройками, миграцией backup v1 и безопасным импортом на другом устройстве.
- Локальный ИИ-помощник вынесен в feature-модуль и доступен постоянной кнопкой в правом нижнем углу без зависимости от платных API.

## Следующие этапы

### P0 — надёжность и качество данных

- Перенести кэш внешних таксонов и фотографии пользователя в IndexedDB.
- Перенести текущий краткоживущий кэш поиска из `sessionStorage` в IndexedDB; добавить TTL-кэш карточек, миграции схемы и ограничение размера.
- Дополнить unit-тесты интеграционными тестами поиска и e2e-сценарием добавления растения.
- Показывать источник, лицензию, автора фотографии и дату получения для каждого внешнего поля.
- Обновлять сохранённый `taxonKey`, чтобы отслеживать изменения accepted name и синонимы.

### P1 — расширение справочников

Подключать источники следует адаптерами, не смешивая поля и лицензии:

- **World Flora Online (WFO)** — мировой список сосудистых растений и мохообразных;
- **Plants of the World Online / IPNI (Kew)** — номенклатура, распространение и публикации;
- **Catalogue of Life** — принятые названия и синонимы;
- **Tropicos (Missouri Botanical Garden)** — номенклатура и библиография;
- **iNaturalist** — наблюдения, фотографии и народные названия;
- **EPPO Global Database** — вредители, болезни и растения-хозяева;
- **USDA PLANTS** — распространение и статусы растений Северной Америки;

Перед интеграцией каждого источника нужны подтверждение бесплатного доступа без billing, проверка API, лицензии, лимитов запросов, правил attribution и доступности из браузера (CORS). При конфликте названий приоритет следует отдавать accepted taxon с сохранением исходного идентификатора каждого справочника.

### P2 — полноценные инструкции по уходу

- Ввести структурированную модель: свет, температура, влажность, субстрат, токсичность, полив, подкормка, обрезка, зимовка и размножение.
- Разделить вид, культивар и пользовательское растение.
- Создать редакторскую очередь и статус проверки материала; не выдавать сгенерированный текст за проверенный совет.
- Добавить регион и климатическую зону, потому что садовый уход не универсален.
- Реализовать сравнение источников и отображение уровня достоверности.

### P3 — продуктовые функции

- Синхронизация между устройствами и аккаунты по желанию пользователя.
- Push-напоминания с серверной подпиской.
- Диагностика по фотографии с вероятностями, предупреждением об ограничениях и историей наблюдений.
- Доступность WCAG 2.2 AA, тёмная тема, локализации и поиск с экранной клавиатуры.
- Виртуализация больших списков, постраничная выдача API и аналитика производительности без сбора персональных данных.

## Отложено до следующих изменений

В текущий этап намеренно не входят IndexedDB, аккаунты и синхронизация, push-уведомления, серверный ИИ,
диагностика по фотографии, редизайн остальных экранов и подключение дополнительных поставщиков данных.
Сначала необходимо стабилизировать вынесенный каталог, проверить лицензии внешних источников и добавить e2e-покрытие.

## Критерии готовности обширной базы

- Поиск не загружает весь справочник в память и поддерживает пагинацию.
- Каждый внешний факт имеет источник и дату получения.
- Синонимы ведут к принятому названию, но остаются доступными для поиска.
- Ошибка одного API не блокирует локальный каталог и пользовательский сад.
- Внешний таксон, добавленный в сад, остаётся читаемым офлайн.
- Медицинские сведения и токсичность показываются только из авторитетных проверяемых источников.
