# Политика бесплатных сервисов PlantCare

## Обязательное правило

PlantCare разрабатывается без бюджета на API и инфраструктуру. Рабочая версия приложения не должна требовать оплаты, привязанной банковской карты, пробного периода или платного тарифа.

Допускаются только:

1. локальная логика в браузере;
2. open-source библиотеки;
3. открытые данные с совместимой лицензией;
4. публичные API без оплаты и без обязательного billing account;
5. бесплатный хостинг в пределах документированных лимитов, при этом приложение должно иметь путь миграции на другой бесплатный статический хостинг.

## Текущие зависимости

| Возможность | Решение | Стоимость | Обязательный fallback |
|---|---|---:|---|
| Основное приложение | React/Vite, статическая сборка | Бесплатно, open source | Локальный запуск через `npm run dev` |
| Хостинг | Vercel Hobby | Бесплатно в пределах лимитов | GitHub Pages, Cloudflare Pages или локальная сборка |
| Научный каталог | GBIF Public API | Бесплатно, без billing key | Редакционный каталог и сохранённые растения доступны офлайн |
| Каталожные изображения | Публичные URL Unsplash | Бесплатно при соблюдении условий источника | Emoji и локальный цветной placeholder |
| PWA и офлайн | Browser APIs + Service Worker | Бесплатно | Обычное веб-приложение |
| ИИ-помощник | Локальный Ollama или доступная browser-модель | Бесплатно для пользователя | Явное сообщение о недоступности; основной уход не зависит от ИИ |
| Данные пользователя | `localStorage`, позднее IndexedDB | Бесплатно, локально | Экспорт/импорт JSON |

Бесплатный тариф внешнего сервиса не считается гарантией навсегда. Поэтому его отказ не должен блокировать основные функции.

## Проверка перед интеграцией

Для каждого нового источника необходимо письменно подтвердить:

- есть ли стабильный бесплатный доступ без банковской карты;
- разрешено ли использование данных и локальное кэширование;
- требуется ли attribution;
- есть ли ограничения частоты и объёма;
- работает ли API напрямую из браузера через CORS;
- какие пользовательские данные передаются;
- что увидит пользователь при недоступности источника;
- можно ли полностью удалить интеграцию без потери пользовательского сада.

Если хотя бы один пункт неизвестен, интеграция не включается в production до проверки.

## Запрещённые архитектурные решения

- платные AI API и ключи с подключённым billing;
- коммерческие базы растений без открытой лицензии;
- обязательная облачная база данных только с временным trial;
- функции, которые перестают работать после исчерпания бесплатной квоты без локального fallback;
- скрытая отправка фотографий растений, заметок или истории ухода третьим сторонам;
- обещание фоновых уведомлений, если оно требует недоступной платной инфраструктуры.

## Приоритет реализации

Сначала используются локальные возможности: IndexedDB, Service Worker, экспорт файлов, Web Notifications в доступных браузерных сценариях и локальные модели. Серверная часть допустима только на постоянно бесплатной основе и не должна быть обязательной для базовых функций приложения.
