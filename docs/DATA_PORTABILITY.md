# Перенос данных PlantCare между устройствами

## Где находятся данные

Приложение развёртывается на Vercel как статическое PWA. Vercel отдаёт код приложения, но не получает и не хранит пользовательский сад. Во время работы данные сохраняются в локальном хранилище конкретного браузера.

Для переноса используется обычный JSON-файл:

1. На исходном устройстве открыть **Мои данные**.
2. Нажать **Экспортировать** — браузер скачает `plantcare-YYYY-MM-DD.json`.
3. Передать файл на другое устройство удобным локальным способом.
4. Открыть тот же сайт PlantCare на Vercel.
5. Открыть **Мои данные**, выбрать JSON и режим **Заменить всё** или **Объединить**.

Запись произвольных файлов на диск без действия пользователя запрещена моделью безопасности браузера. Поэтому экспорт выполняется по кнопке, а импорт — через стандартный системный выбор файла. Платный сервер или аккаунт для этого не требуется.

## Что входит в JSON v2

- все домашние и садовые растения;
- пользовательские и латинские названия;
- добавленные пользователем фотографии в формате data URL;
- интервалы и полная история полива, опрыскивания и подкормки;
- заметки и напоминания;
- расположение растения;
- ссылка на внешний таксон GBIF;
- переносимые настройки приложения (сейчас — последняя активная вкладка; схема допускает последующее расширение);
- версия формата и дата экспорта.

## Совместимость

Текущий формат имеет `version: 2` и поле `app: "plantcare"`. Импорт продолжает принимать старые файлы `version: 1`, добавляя отсутствующие настройки и поля по умолчанию. Неизвестная будущая версия, файл другого приложения или повреждённая запись отклоняются до изменения текущего сада.

## Режимы импорта

- **Объединить** — сохранить текущий сад и добавить растения с новыми ID; настройки текущего устройства не меняются.
- **Заменить всё** — заменить сад данными файла и восстановить переносимые настройки.

## Безопасность и ограничения

- JSON не отправляется на Vercel, GBIF или другой сервер.
- Файл может содержать личные фотографии и заметки; пользователь должен хранить его как личную резервную копию.
- JSON не шифруется, чтобы его можно было открыть и проверить стандартными средствами.
- Изменение файла вручную может сделать его непригодным для импорта.
- После изменений рекомендуется скачать новую копию; автоматическая синхронизация между устройствами намеренно отсутствует.
