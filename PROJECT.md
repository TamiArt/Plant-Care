# 🌿 PlantCare — PWA-приложение для ухода за растениями

Полностью клиентское мобильное приложение (No-Backend PWA) для отслеживания полива и ухода за комнатными и садовыми растениями. Данные хранятся локально в `localStorage`, интернет нужен только для загрузки фото (Unsplash) и научных данных (GBIF API).

---

## Реализованные функции

### Навигация
- **5 вкладок** в нижней панели: Дом · Сад · Каталог · Чек-лист · Добавить
- Бейджи с количеством растений на вкладках Дом и Сад

### Вкладка «Дом» и «Сад»
- Разделение растений по месту: **Дома** (комнатные) и **На участке** (садовые, огородные, уличные)
- Сортировка карточек по срочности полива — самые «жаждущие» всегда сверху
- Счётчик просроченных поливов в заголовке

### Карточки растений (визуальный индикатор полива)
- **Капли воды** — количество заполненных капель = дней до следующего полива
  - 5 капель → поливать через 5 дней; 3 капли → осталось 3 дня
  - Для интервалов >10 дней — масштабирование в 10 капель
- **Подпись под каплями**: «До полива 4 дн.» / «Полить завтра» / «Полить сегодня» / «Просрочено на X дн.»
- Красная рамка и иконка-индикатор на фото при просрочке
- Кнопка **Полить** с предупреждением «Проверьте почву пальцем» перед записью
- Кнопка **Опрыснуть** для тропических растений (с отметкой «Опрыснуто ✓» в день опрыскивания)

### Сезонные интервалы полива
- Зимний режим (ноябрь–март): интервалы автоматически увеличиваются по данным каталога
- Летний режим (апрель–октябрь): стандартные интервалы

### Каталог (29 растений)
- **Комнатные (12)**: Монстера, Потос, Спатифиллум, Замиокулькас, Хлорофитум, Фикус Бенджамина, Фикус лировидный, Орхидея, Алоэ, Кактус, Сенполия, Драцена
- **Розы (3)**: Чайно-гибридная, Плетистая, Парковая (шраб)
- **Хвойные (2)**: Туя западная, Туя «Смарагд»
- **Кустарники (4)**: Гортензия, Сирень, Спирея, Форзиция
- **Огород (5)**: Томат, Огурец, Клубника, Чеснок, Кабачок
- Поиск по названию, латинскому имени и тегам
- Фильтры по категориям: Комнатные / Розы / Хвойные / Кустарники / Огород
- Карточка вида: описание, советы по уходу, болезни, бейдж сложности, предупреждение для «растений-див»

### GBIF — научные данные (живой API)
Подключён к [api.gbif.org](https://api.gbif.org) — глобальной базе биоразнообразия (бесплатно, без авторизации).
При открытии карточки каталога автоматически загружается:
- **Таксономическая цепочка**: Царство › Тип › Класс › Порядок › Семейство › Род
- **Полоса уверенности** определения вида (0–100%)
- **Народные названия** на разных языках (русский, английский, немецкий и др.)
- **Фото из полевых наблюдений** — реальные снимки учёных и натуралистов с attribution
- Ссылка на страницу вида на gbif.org
- Скелетон-анимация при загрузке; graceful fallback при отсутствии интернета

### ИИ-сканирование (симуляция)
- Загрузка фото через камеру смартфона (`capture="environment"`) или галерею
- Режим **«Определить растение»** → анимация сканирования → результат из каталога
- Режим **«Диагностика листа»** → список возможных болезней для найденного вида

### Сезонный чек-лист
- Советы автоматически фильтруются по текущему месяцу
- Категории: Пересадка, Удобрения, Размножение, Полив, Вредители, Опрыскивание, Подготовка к зиме, Свет, Влажность
- Баннер «Зимний режим» / «Активный сезон роста»

### Добавление растений
- Форма: имя растения + ползунок интервала полива + выбор «Дома / На участке»
- Дефолтное место предвыбирается по активной вкладке
- Перемещение растения между Домом и Садом прямо из детальной карточки

### Карточка своего растения
- История всех поливов и опрыскиваний (последние 8 дат)
- Статистика: всего поливов, дата добавления
- Быстрые кнопки «Полить» и «Опрыснуть»
- Переключатель «Дома / На участке» с мгновенным сохранением
- Удаление растения

### PWA
- `manifest.json` + Service Worker для офлайн-кэширования
- Установка на рабочий стол смартфона
- Регистрация SW через `navigator.serviceWorker.register`

### Хранение данных
- Хук `useGarden` — весь CRUD через `localStorage`
- Автомиграция старых записей (добавляет поле `location: "home"` при первом запуске)
- Защита от повреждения хранилища (try/catch с тихим fallback)

## Система хранения данных

### Архитектура хранилища

Приложение полностью клиентское — никаких серверов, никаких баз данных в облаке. Все пользовательские данные живут в `localStorage` браузера под ключом `plantcare_v1`.

```
localStorage
  └─ "plantcare_v1"  →  JSON-массив UserPlant[]
```

### Структура записи растения (`UserPlant`)

```json
{
  "id": "mf3k2a9b1c",          // уникальный ID (Math.random + Date)
  "catalogId": "monstera",      // ссылка на запись в CATALOG[]
  "nickname": "Моя Монстера",   // имя, данное пользователем
  "photo": null,                // data-URL фото с камеры или null
  "wateringInterval": 7,        // дней между поливами (настраивается)
  "wateringHistory": [          // ISO-даты всех поливов
    "2025-06-01",
    "2025-06-08"
  ],
  "mistingHistory": [           // ISO-даты опрыскиваний
    "2025-06-05"
  ],
  "addedAt": "2025-05-20",      // дата добавления в сад
  "location": "home"            // "home" | "outdoor"
}
```

### Хук `useGarden`

Центральный хук управляет состоянием и синхронизирует его с `localStorage`:

| Метод | Описание |
|-------|----------|
| `addPlant(catalogId, nickname, interval, photo, location)` | Добавить новое растение |
| `removePlant(id)` | Удалить растение |
| `waterPlant(id)` | Записать сегодняшнюю дату в `wateringHistory` |
| `mistPlant(id)` | Записать сегодняшнюю дату в `mistingHistory` |
| `updatePlant(id, changes)` | Обновить любые поля (например, `location`) |
| `replacePlants(plants[])` | Полностью заменить массив (используется при импорте) |

Каждый метод вызывает `persist()` — он атомарно обновляет React-состояние и записывает в `localStorage`.

### Автомиграция

При каждой загрузке `loadFromStorage()` прогоняет все сохранённые записи через migration-слой:

```ts
return parsed.map(p => ({ location: "home", ...p }));
```

Это гарантирует совместимость со старыми записями, в которых поле `location` отсутствует.

### Защита от ошибок

```ts
try {
  const raw = localStorage.getItem(GARDEN_KEY);
  return raw ? JSON.parse(raw) : [];
} catch {
  return []; // повреждённое хранилище → тихий fallback к пустому саду
}
```

Аналогичная защита при записи: `QuotaExceededError` (хранилище переполнено) перехватывается молча.

### Экспорт и импорт данных

Пользователь может сохранить и восстановить весь сад через кнопку 🗄️ в заголовке вкладок «Дом» и «Сад».

#### Формат резервной копии (`GardenBackup`)

```json
{
  "version": 1,
  "exportedAt": "2025-06-15T10:30:00.000Z",
  "plants": [ ...UserPlant[] ]
}
```

#### Экспорт
- Сериализует `plants[]` в JSON с отступами
- Создаёт `Blob` и скачивает файл через временный `<a>` тег
- Имя файла: `plantcare-backup-YYYY-MM-DD.json`

#### Импорт
- Читает файл через `FileReader`
- Валидирует структуру: проверяет `version === 1`, наличие массива `plants`, обязательные поля каждой записи
- **Режим «Объединить»** — добавляет только растения, которых ещё нет в саду (по `id`). Текущие данные сохраняются.
- **Режим «Заменить всё»** — полностью перезаписывает текущий сад данными из файла
- При повреждённом файле — показывает сообщение об ошибке, данные не изменяются

#### Сценарии использования
- **Смена устройства**: экспортировать на старом → открыть приложение на новом → импортировать
- **Смена браузера**: тот же сценарий
- **Резервная копия**: периодически скачивать файл на случай очистки данных браузером
- **Несколько пользователей**: каждый ведёт свой файл, при необходимости объединяет через режим «Объединить»

### Что НЕ хранится на сервере

| Данные | Где хранится |
|--------|-------------|
| Список растений пользователя | `localStorage` браузера |
| История поливов | `localStorage` браузера |
| Фото растений (с камеры) | `localStorage` браузера (data-URL) |
| Каталог растений (29 видов) | Статичный массив в коде |
| Научные данные (таксономия) | GBIF API (запрос при открытии карточки) |
| Фото из каталога | Unsplash CDN (по URL) |

## Слабые места

### Данные и надёжность
- **Симуляция ИИ-сканирования** — «определение» выбирает случайное растение из каталога, не анализирует изображение. Реальное распознавание требует подключения Plant.id API, PlantNet или Google Vision.
- **GBIF фото** — URL изображений из наблюдений могут быть нестабильны (404 через время), так как хостятся на сторонних серверах наблюдателей. Реализован `onError` скрывающий битые изображения, но не подставляющий замену.
- **Локальное хранилище** — данные привязаны к браузеру и устройству. Смена браузера или очистка данных = потеря всего сада. Нет синхронизации между устройствами.
- **Привязка к устройству** — несмотря на экспорт/импорт, автоматической синхронизации нет: данные нужно переносить вручную.

### Функциональные ограничения
- **Уведомления о поливе** не реализованы — Push API требует сервер для хранения подписок. Без бэкенда уведомить пользователя вне открытого браузера невозможно.
- **Каталог статичен** — новые растения добавляются только через обновление кода. Нет пользовательских растений, не входящих в каталог.
- **Нет офлайн-кэширования API** — GBIF и Unsplash недоступны без интернета. SW кэширует только статику приложения.
- **Один пользователь** — нет разграничения профилей; всё хранится в одном ключе localStorage.

### UX
- **Нет подтверждения удаления** растения — кнопка удаляет сразу без диалога.
- **Нет поиска по своему саду** — при большом количестве растений навигация затрудняется.
- **Нет редактирования** имени и интервала полива после добавления.
- **Нет статистики** — пропущенные поливы не агрегируются, нет графиков активности.
- **Интервал полива один** — не учитывает изменение сезона для уже добавленных растений (пользователь настраивает вручную).

### Производительность
- **Весь код в одном файле** (~2000 строк) — затрудняет поддержку при росте проекта.
- **Каталог в памяти** — при росте до 200+ растений рендеринг списка стоит оптимизации (виртуализация).
- **GBIF без кэша** — каждое открытие карточки делает 3 последовательных HTTP-запроса. Стоит добавить кэш в `sessionStorage`.
